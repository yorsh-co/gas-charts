# 0002. Own generator for inline script constants

## Status

Accepted

## Context

`gasdev html` builds whole HTML pages and hard-fails when the source contains `</script` (`wrap()` in `gasdev/bin/html.js`). The minified ECharts build may contain such sequences, and we need JS-only string constants rather than pages.

## Decision

- `scripts/generate.js` produces `src/generated/gas-charts.echarts.ts`, mirroring the gasdev output shape: a `// Generated by … Do not edit.` header, `// prettier-ignore`, a `JSON.stringify` literal with U+2028/U+2029 escaped.
- It additionally rewrites `</script` to `<\/script` and `<!--` to `<\!--`. Both are value-preserving only inside string, untagged template and non-unicode (no `u`/`v` flag) regex literals. They would change `String.raw`/tagged templates and break code outside literals (e.g. `a<!--b`), so `generate` warns on stderr with the source file and match count whenever an escape fires, prompting a manual review after an ECharts bump.
- Generated files are committed, ignored by ESLint and Prettier, and `npm run generate:check` (run via `typecheck`, which `npm run check` invokes) fails when they are stale.

## Consequences

- Upgrading ECharts requires `npm run generate`.
- The escaping rules are covered by unit tests rather than relying on gasdev.
